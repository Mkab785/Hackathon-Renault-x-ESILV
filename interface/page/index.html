    Comment fonctionne le traducteur
    Ce que fait le code Python, de l'Excel UserShaker aux codes SysML v2, et comment on sait que le résultat est fidèle.
    

      
    
        
    En une phrase
    
        
    Le traducteur est le dossier Python usershaker2sysml. Il lit l'export UserShaker (.xlsx) sans jamais le modifier, contrôle les données, écrit un code SysML v2 par cas d'usage (plus un code entier), puis relit ces codes de façon indépendante pour vérifier qu'ils disent exactement la même chose que l'Excel. Le site (interface/serveur.py) et traduire.bat appellent tous les deux la même fonction : traduire_complet.
    
      
    

      
    
        
    Le parcours des données, étape par étape
    
        
    Orchestré par traduction_complete.py. Si une étape trouve une erreur bloquante, la suite n'est pas faite : on ne produit pas un modèle faux.
    
        
    
          
    Lire l'Excel
    lecture.py · schema.py
            
    Chaque onglet devient une liste de lignes. Aucune valeur n'est transformée, sauf une cellule vide qui devient « non renseigné ».
    
            
    schema.py recopie le readme UserShaker 1.0 : colonnes, types, valeurs permises, clés.
    
          
    Contrôler les données
    controles.py
            
    Codes E.. (erreur : le schéma n'est pas respecté) et A.. (avertissement : donnée valide mais incohérente ou incomplète).
    
            
    Une erreur sur une donnée utilisée par le modèle bloque la traduction.
    
          
    Fabriquer les noms
    noms.py
            
    « Welcome on board » → WelcomeOnBoard (définitions), « Jacques Martin » → jacquesMartin (usages).
    
            
    Accents retirés, mot réservé SysML → suffixe _, chiffre en tête → préfixe n, doublon → 2, 3…
    
          
    Écrire le SysML
    rendu_cas_usage.py
            
    Un code autonome par cas d'usage, en écriture compacte, sous la limite de CATIA Magic Community (20 000 caractères).
    
            
    Plus un code entier, sans découpage, pour CATIA Magic complet.
    
          
    Relire et comparer
    relecture_complete.py
            
    Les codes sont relus ligne à ligne sans utiliser le traducteur, puis comparés à l'Excel élément par élément.
    
            
    Un écart (étape oubliée, ordre inversé, mauvais besoin…) donne l'erreur E21.
    
          
    Produire les livrables
    trace_xlsx.py · __main__.py · serveur.py
            
    Les fichiers .sysml, le rapport, la traçabilité Excel ↔ SysML (onglets Lisez-moi, Traçabilité, Vérification).
    
            
    Sur le site : téléchargement en zip ; en ligne de commande : dossier sortie.

    Les règles d'écriture
    
        
    
          
    Limite de 20 000 caractèresC'est la limite du Textual Editor de CATIA Magic Community. La taille est comptée avec des fins de ligne Windows (2 caractères), pour ne jamais dépasser même après un copier-coller depuis le Bloc-notes (taille_catia).
    
          
    Écriture compacteLes données répétitives (états, grille, ressentis, groupes) sont regroupées dans des attributs texte, avec leurs identifiants entre crochets. Le code est bien plus court, sans perdre ces données.
    
          
    Un code par cas d'usageChaque code est autonome : il contient les personas, composants et besoins dont il a besoin, et se colle seul dans son propre projet CATIA. Le nombre de cas d'usage est libre.
    
          
    Découpage si trop longUn cas d'usage qui dépasse la limite est coupé en parties, de préférence entre deux groupes d'étapes, sinon entre deux étapes. La partie 1 contient toutes les définitions. Si une étape seule ne tient pas, erreur E22.
    
          
    Rien n'est perduUne persona, un composant ou un besoin rattaché à aucun cas d'usage est écrit avec le cas d'usage 1, pour que toute l'information de l'Excel soit dans les codes.
    
          
    Code entierUn seul code avec tous les cas d'usage (package UseCases), définitions partagées écrites une fois, sans limite de taille : pour CATIA Magic complet. S'il ne peut pas être produit : avertissement E23.

    Ce que fait chaque fichier Python
    
        
    
          
    FichierRôle
    
          
            
    traduction_complete.pyChef d'orchestre : contrôles → écriture → relecture → traçabilité. Renvoie les codes, les problèmes, la vérification.
    
            
    lecture.pyLit le .xlsx (ou des données déjà en mémoire) ; peut réécrire un xlsx corrigé, jamais l'original.
    
            
    schema.pyLe contrat d'entrée : schéma UserShaker 1.0 recopié du readme. Rien n'est ajouté.
    
            
    controles.pyContrôles E.. / A.. avant traduction.
    
            
    noms.pyNoms SysML valides et uniques, liste des mots réservés.
    
            
    rendu_cas_usage.pyÉcrit les codes (un par cas d'usage, découpage, code entier).
    
            
    relecture_complete.pyRelit les codes sans le traducteur et les compare à l'Excel.
    
            
    trace_xlsx.pyFichier Excel de traçabilité.
    
            
    apercu.pyDonnées lisibles pour l'onglet « Aperçu du modèle » et la matrice besoins × étapes.
    
            
    modele_sysml.pyRelit les .sysml (et seulement eux) pour dessiner l'onglet « Modèle lu dans le SysML » et les analyses.
    
            
    controle_omg.pyContrôle facultatif de la grammaire officielle OMG avec SysML2Tools (si installé).
    
            
    contexte_ia.pyChoisit les extraits des codes SysML envoyés à l'assistant IA, dans un budget de tokens.
    
            
    __main__.pyLigne de commande (utilisée par traduire.bat).
    
            
    traduction.py, modele.py, rendu.py, verification.pyAncienne traduction en un seul code résumé. Plus utilisée pour produire les codes, mais certaines de leurs fonctions servent encore (comparaison des noms, colonnes de traçabilité).
